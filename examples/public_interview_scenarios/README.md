# 四个可以真正跑的小练习

代码均为本补充原创，只用Python标准库，在本地临时目录/内存操作。没有网络请求、真实付款、消息broker或硬件操作。它们帮助练习可解释的合同，不能直接部署为生产服务。

## 运行

建议Python3.10及以上。在本目录运行：

```sh
python -m unittest discover -s . -v
```

2026-10-10已经在Python3.12.14、SQLite3.53.1运行33项unittest，通过。完整输出见[实际测试记录](test-output.txt)。这证明给出的测试在该环境通过，不证明全部输入、真实生产故障或其他语言实现都正确。

## 先预测，再打开答案

1. **RRF，对应SC-A03。** 两个列表`[A,B]`和`[B,C]`，k=0，谁排第一？把A重复一次应不应该重复加分？本实现先在单列表按首次出现去重，再分配连续名次；跨列表同ID可累计。实际检索系统需要先统一块ID与窗口策略。测试覆盖精确分数、去重、同分排序和非法输入；没有测真实召回率。
2. **版本写入，对应SC-A10。** 两个编辑者都读取version1，第一个写成version2后，第二个持version1再写会发生什么？锁覆盖“比较与写入”整个步骤，只允许一个成功。它只在一个进程内原子；tenant是存储分区，不是认证与授权。生产需在服务器确认身份，并使用数据库原子CAS/事务。冲突后不要盲目改为当前版本重写，应重新读取并明确合并。
3. **幂等库存，对应SC-A08、SC-A09、SC-B10。** 请求参数相同但key不同表示两次意图；已经成功提交的key换参数应冲突。本模拟把库存修改、订单和成功结果记录放在一个SQLite事务。提交前异常会回滚；提交后丢回复会产生“客户端未知但业务已成功”，用同key重试返回原结果。用不同key重试会再次扣库存。本模型只绑定成功提交的键，库存拒绝和回滚不保留，因此之后可换参数复用；不是“首次尝试即永久预留”或“所有失败都缓存”。没有外部HTTP副作用，因此绝不能将其原子性推广到支付、邮件或其他服务。
4. **TCP应用帧，对应SC-B13。** 一次接收只有2字节header，下一次包含剩余header和部分UTF-8字节，该在哪一步解码？本协议以4字节网络序无符号长度定界，完整payload后再由调用者解码。单帧和输入chunk有上限，协议错误后对象不再复用。若同一次feed先完成好帧再遇错误，异常的completed_frames保留好帧；调用方收集此前返回和异常所带的完整帧，再关闭连接。不能把TCP读取chunk当业务事务边界。测试覆盖所有二段拆分位置、非法尾部、半帧EOF、空消息、多帧和超长输入；真实服务器仍需连接限额、读期限及总工作量限制。

## 代码阅读顺序

先读测试中的预期结果，再读`interview_lab.py`。不要先背实现。每次修改都回答：这保护了哪项不变量？比较与修改是否在同一个原子边界？如果下一行之前进程崩溃，会留下什么？
