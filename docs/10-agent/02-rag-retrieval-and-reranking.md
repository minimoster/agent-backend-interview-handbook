### A09 RAG 从文档到答案的完整流程是什么？

**优先级：P0**

**知识点详解**
- 离线侧先解析、清洗、分块，保留文档 ID、位置、版本与权限；为块建立全文或向量索引。
- 在线侧处理问题、检索候选、去重和重排，在上下文预算内组装证据，再生成答案与引用。这里按常见工程链路展开检索与生成的结合。
- “找到了相关材料”和“最终结论受到材料支持”需要分别验证。检索失败时可澄清、扩检或报告证据不足。

**具体例子** ：问某项目取消逻辑时，先召回代码说明，再找到对应实现和版本；不能引用已过期的设计稿覆盖新代码。

**30 秒答题主线** ：RAG 在生成前或生成过程中引入外部可检索知识。我会讲清数据入库、在线召回、重排、上下文组装和带引用生成，同时单独评估检索与答案，保证权限和版本一路传递。

**追问** ：索引里没有答案怎么办？更新文档后怎样避免旧块残留？

#### 参考答案

索引没有支持证据时，报告证据不足、请求补充或使用获准的其他来源；不能让相似文本冒充答案。更新采用文档身份和版本追踪，删除旧版本块并对账索引，测试“更新后旧事实是否仍被召回”。

**验收点：** 更新一个文档版本并检索旧事实；旧块退出有效召回，无法证实时明确证据不足。

**常见错误** ：把 RAG 说成向量数据库本身；认为接入 RAG 就不会幻觉。

详细流水线为工程设计展开。

### A10 chunk 大小、overlap、父子块怎么选？

**优先级：P0**

**知识点详解**
- 小块更容易聚焦，却可能丢掉条件；大块上下文完整，却可能混入无关主题。先按标题、段落、表格结构切分，再设置长度上限。
- overlap 缓解跨边界的信息损失，但会增加索引量和重复召回。长度单位必须说明是字符还是模型 token，中文尤其不能混用。
- 父子块用小块检索，命中后补回有限父级上下文；这是精确定位与上下文完整性的折中，不是每次返回全文。

**具体例子** ：把“退款条件”和下一段“例外情况”切开会误答；可保留同级章节或通过 parent_id 回补。

**30 秒答题主线** ：我不会宣称某个 chunk size 普遍最优。先尊重文档结构，再用固定问题集比较不同大小和重叠，观察召回、答案质量、延迟及 token；父子块用于补足局部命中的背景。

**追问** ：表格如何保留表头？剩余短块是否一定要补齐？

#### 参考答案

表格块保留表头、行列身份与必要单位；跨块复制表头应保留来源位置，避免变成无来源的孤立数值。短尾块是否合并取决于语义、token 预算和检索表现，不为凑固定长度跨章节拼接。

**验收点：** 将数值表拆成两块；每个检索块仍可确定列名、单位和原文位置。

**常见错误** ：机械按字符截断所有 PDF；为凑满长度把无关段落合并。

### A11 Embedding 是什么？余弦、点积、欧氏距离有什么区别？

**优先级：P0**

**知识点详解**
- Embedding 把文本映射为向量，让一定程度的语义关系能通过几何接近表达。向量相近不是事实相同，更不是证明答案正确。
- 余弦比较方向；点积同时受方向与长度影响。单位归一化后，两者相同；单位向量的平方欧氏距离等于 2−2×点积，因此排序可对应。
- 查询和文档要使用兼容模型与预处理，索引距离要符合模型推荐。换模型即使维度相同，通常也不能直接复用旧向量。

**具体例子** ：“取消运行”和“终止任务”可能语义接近；但订单号 A123 与 A124 只差一个字符，不能因向量接近就当同一订单。

**30 秒答题主线** ：Embedding 提供语义检索信号。我会保证查询与文档处于同一向量空间，并匹配归一化和距离函数；精确标识符仍结合关键词或结构化过滤处理。

**追问** ：向量维度越高越好吗？相似度 0.8 是否就是 80% 可信？

#### 参考答案

更高维度可能提高表达容量，也提高存储与检索成本，效果须在任务数据上比较。相似度 0.8 是特定模型、度量和归一化下的数值，不是经过校准的“80% 答案可信度”。

**验收点：** 固定一组相关性标注比较不同维度/度量；不能把任意0.8分数直接输出为可信概率。

**常见错误** ：跨模型直接比向量；把相似度当概率或授权依据。

### A12 BM25 和向量检索为什么要混合？

**优先级：P0**

**知识点详解**
- BM25 利用词项匹配、词频、逆文档频率和长度归一化。稀有词往往更有区分力，词频增加的收益会饱和。
- 向量检索擅长一定范围内的语义近义匹配；BM25 常对代码符号、产品名、报错文本有用。两者能力互补，但效果取决于分词、语料和模型。
- 先分别得到候选，再融合，最后按需要重排；别直接把不同尺度的原始分数相加。

**具体例子** ：查“context deadline exceeded”需要精确报错；问“任务一直不结束”可能更依赖语义匹配。

**30 秒答题主线** ：我使用混合检索是为了兼顾精确词项和语义表达。BM25 不是过时方案，向量也不是万能。是否混合要用检索标注集验证，再选择排名融合或经校准的分数融合。

**追问** ：中文分词不合理会怎样？只包含精确 ID 的查询如何路由？

#### 参考答案

不合理分词会破坏专有名词、短语与精确标识符的匹配。纯 ID 查询宜优先精确字段/关键词过滤，同时保留权限过滤；不能因文本很短就一概改走向量检索。

**验收点：** 查询一个字母数字ID与一个同义描述，分别验证精确匹配和语义召回，不绕过租户过滤。

**常见错误** ：称 BM25 只是统计词出现次数；未经评测就宣称混合必然提升。

### A13 RRF 怎么算？为什么不直接加 BM25 和向量分数？

**优先级：P0**

**知识点详解**
- RRF 对每一路排名做倒数变换，再按文档累加：score(d)=Σ 1/(c+rank_i(d))。某路未召回该文档，该路贡献为 0。
- 它使用名次，避开不同检索分数尺度不一致的问题，但也丢失了原始分数差距信息。c 是排名平滑常数，不是返回 top-k 的 k。
- 要统一文档/块 ID 并去重，还要固定每路候选窗口；候选没进窗口，融合不可能把它救回来。

**具体例子** ：取教学值 c=10，文档甲两路都排第2，分数为 2/12；文档乙只在一路排第1，分数为 1/11，甲反而更高。

**30 秒答题主线** ：RRF 融合的是排名，解决异质检索分数不好直接比较的问题。每个候选累加各路的倒数名次分数。我会区分平滑常数和 top-k，并通过评测决定召回窗口和是否需要加权。

**追问** ：两路重复文档如何处理？RRF 常数改变会怎样？

#### 参考答案

按稳定文档或块身份合并两路重复项，再累加各路排名贡献；保留来源和版本。RRF 常数变大会减弱头部名次差异，相对鼓励多路共同出现；调参应固定候选集与评测集。

**验收点：** 同块在两路出现时只保留一个身份但累加两路排名贡献；来源版本不会丢失。

**常见错误** ：把融合分数当余弦相似度；把某个厂商默认常数说成数学定理。

### A14 Rerank 做什么？Cross-Encoder 与 LLM rerank 有何不同？

**优先级：P0**

**知识点详解**
- 召回负责从大语料找一批候选；重排对这批候选作更细判断，通常只保留较少证据给生成模型。重排无法找回候选集里完全没有的内容。
- Bi-Encoder 可离线编码文档，适合快速召回；Cross-Encoder 联合处理 query 与文档，让两者细粒度交互，代价是逐对计算。
- LLM rerank 让生成式模型输出分数或排序，需额外处理输出格式、顺序偏差、超时和费用。它不能被笼统称为 Cross-Encoder 实现。

**具体例子** ：召回得到多个“重试”文档，重排需区分 HTTP 重试与业务任务重试。Saber 当前链路是 LLM rerank，面试应按代码说。

**30 秒答题主线** ：重排用更多计算换候选排序质量，常放在召回之后。Cross-Encoder 和生成式 LLM 排序是不同实现。我的项目若使用 LLM rerank，就会讲清格式校验和成本，不冒称部署过专用重排模型。

**追问** ：重排让效果下降怎么办？候选顺序变化会影响 LLM 排序吗？

#### 参考答案

固定检索候选比较重排前后，检查截断、提示、解析失败、延迟和相关性标签；支持回退而非强制所有查询重排。LLM 列表排序可能受位置与列表构成影响，应打乱顺序、重复运行并校验输出索引、重复项和候选覆盖。

**验收点：** 乱序输入固定候选并注入非法排序索引；验证重复、遗漏、解析失败及回退结果。

**常见错误** ：说重排总比召回准确；把用了 rerank 等同于训练了 reranker。

Saber 的具体检索与重排实现见[项目A43](../50-projects/public-repository-case-studies.md#a43)。

### A15 Query rewrite、多 query、HyDE 为什么可能有用，也可能有害？

**优先级：P1**

**知识点详解**
- 改写可消解多轮对话中的指代，把口语问题变成可检索问题；多 query 从不同角度补充召回，但会引入重复和费用。
- HyDE 先生成假设性答案/文档，再编码并检索真实文档。假设文本只是查询桥梁，其中可能含错误，不能直接当最终证据。
- 工程上应保留原问题，避免改写丢掉否定、时间、实体或权限范围，并比较不改写的基线。

**具体例子** ：“它支持取消吗？”需从对话知道“它”指 Openresearch；若改成“所有 Agent 如何取消”，检索范围就漂移了。

**30 秒答题主线** ：我用改写解决表达与检索语料之间的差距，但要防止语义漂移。多 query 要去重并控制数量；HyDE 生成的内容只是用来找真实资料，最终答案仍必须依据真实来源。

**追问** ：怎样发现改写把“不支持”改成“支持”？何时跳过改写？

#### 参考答案

使用带否定、日期、版本和精确 ID 的配对测试，比较改写前后意图与证据。精确检索、已明确约束的短查询或改写不确定时可跳过；保留原查询一路，避免一次改写成为唯一入口。

**验收点：** 使用“不要2025版、只查2026版”配对查询，确认改写没有消除否定或版本约束。

**常见错误** ：直接引用假设文档；只看召回数量增加，不看相关性和成本。

改写校验为工程建议。

### A16 RAG 答错了，按什么顺序排查？

**优先级：P0**

**知识点详解**
- 先判断知识库有没有正确材料，再查解析是否损坏、分块是否断义、索引是否最新、权限过滤是否误排。
- 接着检查正确块是否进入召回候选、是否被重排淘汰、是否在组装上下文时被截断；最后才检查生成是否误读或编造。
- 做“给定正确证据”的对照：模型拿到正确材料仍答错，重点改生成；给对证据就能答对，优先查检索链。一个终局分数不能定位全部问题。

**具体例子** ：文档有取消 API，检索却只返回启动 API；此时单纯改“请准确回答”的 prompt，不会补出缺失证据。

**30 秒答题主线** ：我会顺着数据到答案的链路排查，并保存每阶段中间结果。先确认正确资料存在，再查召回、重排、上下文组装和生成。通过注入正确证据做对照，把检索失败与生成失败分开。

**追问** ：检索相关但答案不受支持是什么问题？如何复现线上 bad case？

#### 参考答案

候选相关但答案不受证据支持，优先检查上下文选择、引用映射和生成阶段，而非立即更换 embedding。复现须保存模型/索引/提示版本、权限过滤、候选、排序、最终上下文和失败断言；敏感信息须最小化。

**验收点：** 保存一条检索相关但引用不支持答案的轨迹，能定位候选、上下文和最终断言三个阶段。

**常见错误** ：任何答错都换更大模型；只凭最终文本猜故障层。

### A17 Recall@k、MRR、NDCG 分别衡量什么？

**优先级：P0**

**知识点详解**
- Recall@k 看已知相关文档中有多少进入前 k；Precision@k 看前 k 里多少相关。必须先有清楚的相关性标注及统计单位。
- MRR 关注第一条相关结果出现多早，对单个最先可用结果的任务直观；NDCG 可以表达分级相关性并折扣靠后的结果。
- 检索指标衡量候选质量，不能直接称为最终答案准确率。标注只覆盖部分相关文档时，离线指标也有局限。

**具体例子** ：已知3个相关文档，前5名找到2个，则 Recall@5=2/3、Precision@5=2/5；第一条相关在第2名，该查询的倒数排名为1/2。

**30 秒答题主线** ：我会按业务选指标。需要找全证据就重视 Recall，需要尽早给到可用结果就看 MRR，存在多级相关性可看 NDCG。检索和答案分别评估，不能把命中率当整个 RAG 的正确率。

**追问** ：k 增大会对精度、召回和成本产生什么影响？一问多个相关块怎么算？

#### 参考答案

k 增大可能改善召回，但并不保证每个查询单调改善最终答案，且常增加噪声、重排和上下文成本。多相关块时，先声明按块、文档还是去重证据集合标注，Recall@k 的分母是该口径下的相关项数量。

**验收点：** 两份相关文档各有多个块时分别计算块与文档Recall@k，写明去重及分母。

**常见错误** ：把“任意命中一个”的 Hit@k 与 Recall@k 混用；不写分母。

### A18 RAG、微调、LoRA 应怎么选？

**优先级：P1**

**知识点详解**
- RAG 在推理时提供外部材料，适合经常更新、需要引用或按权限控制的知识；微调改变模型参数，常用于稳定任务行为、风格或领域能力。
- LoRA 是参数高效微调方法，以低秩矩阵表示权重更新，通常冻结原权重；它不是检索算法，也不保证事实实时更新。
- 两者可组合：检索负责供证，微调改善使用证据、格式遵从等行为。选型还要考虑标注数据、训练与部署维护成本。

**具体例子** ：每天变化的内部公告适合索引更新；大量稳定的工单分类示例可以先比较提示词与微调。

**30 秒答题主线** ：我先判断问题是缺知识还是行为不稳定。可更新、可追溯的知识优先检索；有足够数据且需要稳定行为时再评估微调。LoRA 减少需要训练的参数；检索知识更新与训练行为优化可以分别评估。

**追问** ：微调是否能降低幻觉？训练集和评测集如何隔离？

#### 参考答案

微调可改善行为、格式或领域任务，但不提供最新外部证据，也不保证消除幻觉。按实体、来源、时间或任务模板分组划分数据，去除近重复；最终测试集不参与模型、提示或阈值选择。

**验收点：** 把同一实体/模板的近重复样本放入分组划分检查，确认测试集未参与阈值或模型选择。

**常见错误** ：说 RAG 完全不需要任何模型训练就否定其组件可能经过训练；把调用 LoRA 模型当成自己完成微调。
