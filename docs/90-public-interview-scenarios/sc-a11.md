# SC-A11 SSE断开后续传的是事件还是业务任务

[返回场景卡目录](README.md)

**练习问题：** Agent结果通过SSE流式显示，浏览器断开又连接。是否应该重新启动Agent任务？

**知识点详解**： SSE传服务器到客户端的事件；业务任务是否运行是另一份状态。网络连接断开不代表任务失败，连接重建也不应默认产生新任务。

## 参考答案

创建任务返回稳定task ID，事件有单调序号或唯一ID，服务端保存可恢复的事件与最终状态。客户端重连带Last-Event-ID，服务器按保留策略补发后续事件；客户端按ID去重。超出保留窗口时返回当前快照或明确不可续传。取消任务使用独立授权接口，并处理任务已完成的情况。

## 追问1：HTTP响应开始后，工具失败如何显示？

已发送的状态码不能改成新的错误响应。用有类型的error或terminal事件描述结果，最终业务状态落库；“收到token”不能当“任务成功”。

## 追问2：TCP每次read拿到一条SSE事件吗？

不保证。接收块可能拆分UTF-8字符或包含多条消息。遵守SSE行/空行解析合同，不能用一次read对应一次event。

## 常见误区

重连创建新任务；只记在浏览器内存里；用最后一个token证明完整成功；只保持连接却不做背压和资源清理。

## 练习与验收

创建编号1–5的事件，客户端在3处断开，从3续传，并模拟重复3。验收界面最终只出现1–5一次；缺失历史应给出明确恢复路径。完整 SSE 解析器仍待实现与测试。
