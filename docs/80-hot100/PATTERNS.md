## 先理解六种状态

1. 历史摘要：两数之和保存出现过的下标；和为K的子数组保存前缀和频次。问题不同，不能机械复用字典值类型。
2. 合法区间：无重复子串维护窗口内互异；最小覆盖维护目标字符缺口。一个在违法时缩窗，一个在合法时尽量缩窗。
3. 未决候选：每日温度的栈存还没遇到更热天的下标；滑动窗口最大值的队列存还没被更优数支配的下标。
4. 子问题答案：树高返回单分支高度；树的最大路径和更新可跨左右的全局答案，但只向父节点返回一侧。
5. 可行选择前缀：回溯的路径是一个尚未完成的答案，撤销操作必须把状态恢复到进入该分支之前。
6. 已求最优值：DP状态必须带明确范围，“dp[i]是最佳结果”不够，要补上处理了哪些元素、是否必须选择当前元素。

## 五条重要迁移链

### 哈希与前缀和：1 → 560 → 437

1问“补数是否出现”；560问“某个历史前缀出现过多少次”；437把数组前缀搬到树路径，离开一条路径时必须撤销频次，避免把兄弟分支误拼成一条路径。

### 链表反转：206 → 234 → 25

先处理整条链，再把反转用作检测回文的中间步骤，最后限制为k长度分组。始终先保存将被断开的后继，明确旧头如何连接剩余部分。回文检查后是否还原输入，要与页面契约一致。

### 单调结构：739 → 84 → 239

739在弹栈时确定“下一个更大”；84在弹栈时确定“能延伸的最宽范围”；239还要按时间窗口过期，所以使用能从两端删除的deque。

### 子集与背包：78 → 416 → 322

78枚举所有选择，416把可达总和合并为状态，322允许硬币重复使用。0/1背包倒序更新避免同一元素重复用，完全背包正序更新允许重复用；顺序来自使用次数的约束。

### 二维搜索：74 ↔ 240

74的行之间完全衔接有序，可以在逻辑一维数组上二分；240只有行列分别有序，使用角落排除法。不要因为两个接口同名就忽略前提差异。

## 一道题的三次复习

- 第一次：能手推页面自拟例子，说明每个变量存什么。
- 间隔一天：不看答案重写，跑最小输入、极端输入和随机对拍。
- 间隔一周：两分钟口述朴素法瓶颈、优化观察、正确性依据、复杂度和一个会写错的边界。再改变一个前提，判断原算法是否还成立。

## Python实战检查表

- 字典和集合在通常哈希模型下平均常数查找；字典键和集合元素必须可哈希。列表不可哈希；元组只有在每个元素都可哈希时才可哈希。26个整数构成的计数元组可哈希，含列表的元组不可哈希。不可变容器不等于任意内容都可哈希。
- `list.pop(0)`线性；队头删除用`deque.popleft()`。
- `nums[1:]`、`s[i:j]`与`sorted(nums)`都有复制成本。
- `[[0] * n] * m`会共享行对象；应使用列表推导创建独立行。
- 默认递归深度有限，深链表/退化树优先显式栈。仅提高递归上限不是自动证明安全。
- 节点相交判断看身份，不能只比较值。
- 单测最好用独立的朴素参考算法，别复制主解再对拍自己。

例如，`counts = (1, 0, 2)`可作为字典键，`groups = {counts: ["acc"]}`合法；`hash(([],))`会抛出`TypeError`，把任意列表外层转成元组并不足够。LC49使用整数计数元组，满足元素条件。语义见[Python可哈希定义](https://docs.python.org/3.10/glossary.html#term-hashable)。
