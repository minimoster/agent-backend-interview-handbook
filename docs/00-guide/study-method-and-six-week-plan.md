# 阅读指南与六周路线

面向准备第一份开发实习的学习者。覆盖 AI Agent 与大模型应用开发、后端通用基础、Go 与 Java。你不需要把每个方向同时学到同一深度：先建立后端与 AI 应用的共同底座，再选择一个主语言，用能运行、能解释、能测试的小项目把知识串起来。

这份手册的目标是让你能解释原理、举出例子、描述取舍并承认边界。题目用于发现知识缺口，不承诺押中任何公司的面试，也不把他人的面经视为招聘要求。

## 从哪里开始

第一次阅读建议按“使用方法 → 六周路线 → 后端通用 → 主语言 → AI Agent → 真实面经”走。若正在投 Agent 岗，可把 AI Agent 提前，但不要跳过 HTTP、并发、数据库与失败处理。Go、Java 两章都可读，主修一门，另一门只建立比较框架。

- P0 必须会：能不用提示说清核心机制，写最小例子，处理常见追问。
- P1 应该会：理解适用条件与取舍，能结合项目展开；暂时不会不影响先投递。
- P2 拓展：用于辨别深度和继续学习，先定位、再按岗位补齐。

优先级是本手册面向首份实习的学习建议，不是统计得到的考频。阅读一题时，先看题目，合上详解独立回答 60–90 秒，再读原理和例子，最后用追问验证是否真的理解。

### 每道题怎样学

1. 先理解它解决什么问题。把专有名词改写成一句自己的话。
2. 做一个最小实验。能运行就运行；暂时没环境时，先手写输入、执行顺序和输出。
3. 解释失败条件。正常路径容易记，边界、并发和故障最能检验理解。
4. 练一段有因果关系的回答：结论 → 机制 → 例子 → 取舍。面试答法是示例，不是个人经历。
5. 给自己记一个状态：未学 / 能解释 / 能复现 / 能追问。只有最后两档才算准备扎实。

不要一天逐题通读几十页。建议一次集中学习 3–5 题，完成一个小实验；每天用 10 分钟复述昨天的两题。遇到生词时先顺着题内解释读，再回来源查细节。

## 六周学习路线

默认每周 5 天，每天约 1.5–2 小时，周末留出一次复盘。若时间更少，把周期拉长，不必用跳过实验来换进度。题号应按章节里的实际主题选择；没有完成先修知识时，可以把这一周重复一次。

| 周次 | 学习重点 | 当周实践 | 验收标准 |
| --- | --- | --- | --- |
| 第 1 周 | HTTP、TCP、进程线程、数据库与 SQL；选择 Go 或 Java 作为主语言 | 写一个健康检查与简单查询接口，记录请求与错误 | 能解释一次请求如何到达服务，能读懂自己的调用链 |
| 第 2 周 | 主语言基础、内存与并发、集合、错误处理、测试 | 加参数校验、超时取消、单元测试；手写常见容器与并发例子 | 能解释三段自己改过的代码，能定位一个并发或空值问题 |
| 第 3 周 | MySQL 索引事务、Redis、缓存、消息队列与可靠性 | 给接口加数据库与缓存；模拟重复请求、缓存未命中与失败 | 能画数据流，说明一致性方案及其限制 |
| 第 4 周 | LLM 调用、结构化输出、RAG、向量检索与工具调用 | 用小型可公开语料做带来源的问答；加入至少一个受控工具 | 能区分检索失败与生成失败，能解释工具权限与失败路径 |
| 第 5 周 | 评测、观测、成本、部署与安全 | 做固定测试集，统计正确率、延迟与 token 使用；复现一个失败案例 | 指标有样本、口径和记录，能说明一次改动为何有效或无效 |
| 第 6 周 | 项目表达、基础复习、算法与真实面经练习 | 每两天一次模拟面试；每日一道数组/哈希/链表/树基础题并复盘 | 能连续讲 3 分钟项目，回答两层追问，明确不知道的部分 |

这是一条学习路线，不是要求你在六周完成生产级平台。项目功能可以少，但关键路径要由你亲自读懂、测试并复现。算法题量不要为了数字增长；对每题说明复杂度、边界输入和为什么正确。

### 每天两小时的安排

- 15 分钟：闭卷复述前一天两题，标出卡住的概念。
- 40 分钟：学习 3–5 道相关题，画数据流或执行过程。
- 45 分钟：做一个实验、写测试或定位一个失败。
- 20 分钟：录一段回答，记录证据和仍不确定的地方。

## 用一个小项目串起四章

可以做“可追溯的资料问答与任务助手”：用户上传自己有权使用的资料，系统解析并建立索引，回答时显示引用；只有获得授权，才调用少量受控工具。不要接入真实付款、删库、群发等高风险动作作为入门实验。

第一版只需要用户输入、后端接口、检索、模型回答、引用与日志。第二版再加队列、缓存、评测和权限。数据量、延迟、成本和效果都应在自己的环境测量，不能把演示系统称为大规模生产系统。

### 请求与风险的主流程

用户输入 → 身份与输入校验 → 请求预算与超时 → 检索或工具规划 → 权限与参数检查 → 执行 → 结果校验与来源 → 回答 → 日志与评测。

失败时先判断发生在哪一段。检索不到资料不等于模型太弱；工具调用失败不等于要无限重试；回答有 JSON 格式也不等于字段语义正确。每一段都应知道输入、输出、失败信号与允许的处理方式。

### 建议保留的项目证据

- 一张架构图，标出进程、数据存储和第三方边界。
- 一份能从头启动的 README，说明环境、依赖版本与已知限制。
- 至少一条完整请求日志，敏感信息脱敏，不记录密钥。
- 一组固定测试样本，包括正常、无资料、格式错误与工具失败。
- 一次优化前后的对比：相同样本、相同指标口径、明确实验环境。
- 一段你亲自定位并修复问题的记录，写清假设、证据与验证。

## 使用 AI 辅助代码时怎样诚实回答

“用过 AI”不是贡献的说明。面试官通常需要知道你能否独立判断生成结果、解释关键逻辑并承担调试工作。把经历分为“我独立完成”“我在辅助下完成”“我只读过或试过”三层，回答时保持一致。

可使用这样的表达模板，并替换成真实事实：“项目中我用 AI 辅助生成了部分基础代码。我自己负责阅读和修改的部分是……，我补了……测试，发现过……问题，并用……验证。对于……底层实现，我目前知道接口和原理，还没有独立实现。”

不要声称自己做过没有做过的生产部署、百万级并发、模型训练、真实用户运营或团队职责。教程复现可以写成教程复现；基于开源项目的改造要说明基础来自哪里、具体改了什么。面试答法中的“例如”与“如果我设计”不应被改写成已经发生的经历。

### 当你不知道时

先明确边界，再给可验证的推理：“这个版本的实现细节我不确定。我知道它需要保证……，如果让我排查，我会先检查……，再通过……实验验证。”可以推导，但不要把猜测说成事实。追问超出准备范围时，宁可停在可信的一层。

### 项目贡献自查

| 检查点 | 可以带进面试的证据 | 常见风险 |
| --- | --- | --- |
| 我是否能解释代码 | 输入输出、核心数据结构、错误路径 | 只会复述文件名和框架名称 |
| 我是否真正验证 | 测试用例、运行记录、失败复现 | 代码能启动就认为正确 |
| 我是否测过效果 | 样本、指标定义、原始结果 | 把主观感受包装成提升百分比 |
| 我是否知道边界 | 版本、容量、权限、已知缺陷 | 把实验原型描述成生产系统 |
| 我是否有独立判断 | 一次方案取舍与依据 | 所有理由都是“AI 推荐这样写” |

## 来源与阅读边界

本手册分为“知识详解”和“真实公开面经”两类。知识章节是根据可核验资料整理的学习讲解；公开面经是发帖者的个人经历，不是公司背书或经过独立验证的招聘记录。原创练习与延伸追问不算真实面经。

来源优先使用语言规范、官方产品文档、标准与原始技术资料。社区面经保留链接、可见日期和获取限制；若只能看到摘要，必须明确标注，不能补造流程、题目或结果。无发布日期的动态文档以访问日期记录，不能把访问日期当作发布日期。

软件文档会变化。并发运行时、API、框架默认值、协议、模型能力和安全建议都应结合具体版本核对；本册未锁定的内容不能自动视为你正在使用版本的保证。来源的详细记录见书末索引及 ZIP 内 JSON 文件。

## 面试前一晚与当天

前一晚只复习 P0、自己的项目图、两段故障排查经历和错题。准备一份你真实掌握的技术栈说明，以及三项希望了解的问题：实习任务、指导方式、考核或协作方式。不要临时把新名词加进简历。

当天先确认问题边界。答基础题时先给短结论，再解释机制；答设计题时先问业务目标和约束，再说明数据流、失败与取舍；答项目题时区分团队做了什么和你做了什么。

结束后记录被问到的原题、自己的回答、卡点和要补的实验。记录自己的真实面试经历时，遵守面试中的保密约定，不记录他人个人信息或未公开业务资料。

## 一页学习记录模板

把下表复制到自己的笔记。状态只能根据实际表现推进：能复述不等于能复现；看过答案后觉得懂了，不等于能回答追问。

| 日期 | 题号与主题 | 当前状态 | 下一次验证动作 |
| --- | --- | --- | --- |
| 待填 | 例如 B01 HTTP 方法 | 未学 / 能解释 / 能复现 / 能追问 | 写一个重复请求例子并说明副作用 |
| 待填 | 选择一题主语言基础 | 待填 | 写最小代码和边界测试 |
| 待填 | 选择一题数据库问题 | 待填 | 展示查询计划或并发执行顺序 |
| 待填 | 选择一题 Agent 问题 | 待填 | 设计一个失败样例并验证处理 |
| 待填 | 自己项目的一次改动 | 待填 | 记录改动前后证据与仍未解决的问题 |

每周复盘时只回答三个问题：哪些题能闭卷说清；哪些题缺实验；哪些简历表述超出了现有证据。下一周先补最后两项，再增加新题。
