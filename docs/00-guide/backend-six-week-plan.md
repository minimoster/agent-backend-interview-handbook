# 六周复习路线

[返回总目录](../../README.md) · [题目索引](../../QUESTION_INDEX.md) · [版本与纠错](../../errata/README.md)

**定位建议**： 以 Go 为主线，把数据库、网络和工程正确性作为共同底座。Java 用来读懂基本业务代码、理解框架概念与扩展岗位选择；六周内不建议同时宣称 Go、Java、AI Agent 和分布式系统都精通。以下是原创学习计划，可按每周 5 天、每天约 2—3 小时执行；时间较少就延长，不通过熬夜硬压缩。

**每天的固定结构**： 35 分钟理解一个主题；35 分钟写实验或修项目；40 分钟算法/SQL；20 分钟不看稿口述与记录错因。周末留一次 45 分钟模拟面试和一次项目验收。总题量让位于独立完成质量。

### 第1周 打通请求与 Go 基础

- 后端重点：B01—B08、B42。能画出一次请求的应用层与传输层关系，解释 HTTP 幂等、TCP 消息边界、TLS 与 SSE。
- Go 主线：基础类型、slice/map、错误处理、函数、接口、包与测试；写一个有输入校验和结构化日志的 HTTP 服务。
- 算法：数组、哈希、双指针，选择约 6—8 题；每题写复杂度与两个边界样例。
- Java 补充：只读基础语法、类与接口、集合、异常，完成一个小函数；暂不并行搭建另一套大项目。
- 验收：独立写一个查询接口；能解释 GET/POST 取舍、错误码和参数验证；一分钟讲清项目解决什么问题。

### 第2周 把 SQL 与事务真正跑起来

- 后端重点：B09—B21。任选 MySQL 或 PostgreSQL 为项目主库，明确具体版本；另一个只做关键差异对照。
- 实验：建订单与库存小表；设计两种索引比较计划；用两个数据库会话复现 RC/RR 差异与并发扣库存。
- SQL：过滤、连接、分组、NULL、Top-N，各做 2—3 道；写出“正确结果为何如此”。
- 算法：二分、链表、栈队列，约 6—8 题，重点练边界和指针更新。
- 验收：能解释一条慢 SQL、一个事务竞态与修复措施，保存实验步骤及真实测量结果。

### 第3周 缓存与并发控制

- 后端重点：B22—B30、B36、B41。先做旁路缓存，再人为制造并发未命中和删除失败。
- Go 主线：goroutine、channel、mutex、context、有界并发和 race 检测；能清楚说明共享状态归谁管理。
- 项目：加入缓存 TTL、请求合并、回源并发上限和取消；画出 B26 的旧值回填时序。
- 算法：滑动窗口、树 DFS/BFS，约 6—8 题；分别说明窗口单调条件和遍历不变量。
- 验收：并发压测时系统资源有边界；缓存失效时不会把全部请求无上限打到数据库。

### 第4周 消息与可靠执行

- 后端重点：B31—B39。用一个异步文档处理任务理解重复、重试、outbox 和幂等。
- 实验：在“业务提交后、位点提交前”故意终止消费者，验证重放不会重复产生本地业务效果。
- Java 补充：了解 JVM 的运行概念、线程与执行器、Spring Boot 的请求入口与依赖注入；只练一个小接口，与已有 Go 接口做对照。
- 算法：堆、回溯和基础动态规划，约 6—8 题，优先讲清状态定义与转移，不急着刷难题。
- 验收：能讲一次失败从发生到恢复的全过程，明确哪些效果可重复、哪些需要额外保护。

### 第5周 把项目做成可检查的工程作品

- 后端重点：B40、B44—B48。补充 Docker、多阶段构建、配置、探针、优雅退出、指标与 trace。
- Agent 项目建议：做一个范围明确的文档问答/工具调用服务，具备文档导入、检索、流式响应、取消、鉴权、限流与错误记录。先把固定工作流跑稳，不必为了名字叫 Agent 而堆叠自主规划。
- 验证：分别模拟数据库慢、模型超时、用户断线、重复任务和服务终止；为每个故障写预期行为。
- 练习：SQL 复杂连接与窗口函数；复做前四周错题，不再只追求新题数量。
- 验收：别人按 README 能复现；所有性能数字注明数据规模、并发数和测试环境，不编造生产经历。

### 第6周 按岗位说明查漏补缺并投递

- 用真实岗位说明建立“已实践、能解释、待补齐”清单。Go 后端岗位深挖 Go 并发与数据库；Java 岗增加集合、并发、JVM、Spring；Agent 岗增加检索评估、工具调用边界与成本/延迟分析。
- 做 3 次模拟：基础知识 30 分钟、项目追问 30 分钟、算法加 SQL 45 分钟。录下表达，优先修复说不清的因果关系。
- 简历只写能现场讲清或展示的内容。推荐表述为“主要使用 Go 完成……，了解 Java/Spring 基础”；不要用“精通所有中间件”遮盖实际经验。
- 投递与学习并行：每次面试记下原题、自己的回答和缺口，再回到官方来源修正。不要等全部 P1 都学完才开始尝试。
- 验收：随机抽 10 道 P0，至少 8 道能独立讲机制、举例并回答一个失败场景；项目中的每个组件都能回答“为什么需要”和“不用会怎样”。这个标准是自测建议，不是录用保证。
