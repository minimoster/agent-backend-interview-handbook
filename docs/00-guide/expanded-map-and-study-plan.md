# 全主题怎么学：先建立主线，再按追问补深度

[返回总目录](../../README.md) · [原六周细化路线](study-method-and-six-week-plan.md) · [题号索引](../../QUESTION_INDEX.md)

这份扩展讲义适合第一次准备技术实习的学习者。主题多，不意味着每个主题都要同时背完。六周的目标是形成一条能够解释、实现、验证的主线；剩余主题作为追问库与复习地图。学习速度取决于基础和可用时间，不能保证按日程就能获得实习。

## 先选一门主语言

- **Java主线：** JavaSE → 集合 → JUC → JVM → Spring/MyBatis → 数据库/缓存 → Agent应用。Go章先阅读并发取消和HTTP概念对照，需要投Go岗位时再系统补全。
- **Go主线：** 类型/接口 → goroutine/channel/context → 同步/竞态 → HTTP与数据库 → 可靠执行 → Agent应用。Java章作为跨栈知识库，不要求同步掌握全部框架细节。
- **AI Agent主线：** 工具调用与状态 → RAG → 记忆与上下文 → 持久任务与审批 → 评估与权限 → 复杂编排。先把一个可靠单Agent讲清楚，再判断多Agent是否带来真实增益。

所有语言路线都需要HTTP、SQL、并发、错误处理和基本测试。更换主语言不能代替这些共同基础。

## 六周节奏

默认每天约90–150分钟、每周5–6天；时间不足时延长周期，不用压缩理解与验证。每天选择2–4道核心题，比快速浏览十几道更适合作为起步。

| 周次 | 核心学习 | 当周可交付证据 | 常见失速点 |
|---|---|---|---|
| 第1周 | 主语言基础、集合、HTTP请求链路、SQL基本查询 | 一张请求流图；3个边界测试；能解释值/引用、错误与数据类型 | 只记术语，解释不了代码实际行为 |
| 第2周 | 并发/取消/线程池或goroutine、事务/索引/缓存 | 超时取消小实验；两种索引计划对比；事务失败时间线 | 把“并发安全”或“用了事务”当完整答案 |
| 第3周 | 单Agent loop、工具参数、RAG基础与权限过滤 | 一个可复现的工具调用任务；检索失败样例；引用与拒答规则 | 工具能调用就认为Agent已可靠 |
| 第4周 | 记忆、上下文、持久状态、重试/幂等、流式协议 | 同一任务重复投递不重复写；取消后的资源清理记录 | 为了成功演示省略超时和失败路径 |
| 第5周 | 评估、Harness、多Agent取舍、安全与场景设计 | 固定小评测集；单/多Agent对照；至少3种故障注入 | 仅看输出流畅度，忽略成本和回归 |
| 第6周 | 岗位定向复习、SQL/算法、项目表达、模拟追问 | 2次计时模拟；1页项目证据表；可复验的失败修复记录 | 追求覆盖全部名词，却没有能讲深的主线 |

## 每道题的五步练法

1. **先读问题，不看答法。** 写下自己现在的解释，哪怕只有两句话。
2. **阅读知识点和例子。** 用自己的数据重新走一遍，找出每个条件起什么作用。
3. **制造反例。** 去掉唯一键、制造重复消息、让工具超时、把登录时间移到年末边界，观察结论是否仍成立。
4. **再说30–60秒答案。** 先定义，再讲机制，接一个失败边界，最后说明取舍。
5. **记录证据，不记录表演。** 保存代码版本、输入、命令、结果和限制；没有做过的实验就保持“待做”。

若能复述却不能解释具体反例，返回知识点；若能解释但写不出来，补最小代码；若能运行但不知为何，缩小实验，先验证一个机制。

## 从主题到任务

| 主题族 | 最小实践任务 | 什么才算理解 |
|---|---|---|
| Agent/开发框架/范式 | 一个有终止条件的工具循环，画出状态转移 | 能解释何时继续、重试、停止与交给人 |
| Vibe coding/Harness | 给编码任务写验收合同并让独立检查发现一个缺陷 | 能区分“模型说完成”与测试/规则证据 |
| Memory/上下文 | 同一用户跨任务保留一条偏好，再修改与删除 | 能说明作用域、写入来源、失效与权限 |
| 多Agent/自改进 | 单Agent基线与双角色方案使用同一组任务比较 | 能解释协调成本、失败归因与上线回滚 |
| MCP/Skill | 画工具协议边界和技能包加载边界 | 知道协议版本、权限、执行环境分别负责什么 |
| RAG | 构造一次检索命中但答案错误的案例 | 能区分召回、排序、证据使用和回答评估 |
| Java/JVM/JUC | 一段可解释的并发实验与线程/堆观测 | 能连接语言语义、运行时和可观测证据 |
| Go | context取消、错误收集、无泄漏退出 | 能解释通道所有权和各退出路径 |
| MySQL/SQL/MyBatis | 查询边界、事务失败和参数绑定练习 | 能说明题意、数据粒度、NULL和版本限制 |
| Redis/MQ/分布式 | 重复消费、缓存过期和锁租约失效实验 | 能证明业务不变量，不只演示组件可用 |
| 网络/OS/Linux | 从一次请求超时定位到连接、进程或资源层 | 能按证据排查，而不是列命令清单 |
| 设计模式/场景/项目 | 给同一需求设计简单版，再解释何时扩展 | 能区分需求驱动的结构与为用模式而用模式 |
| 智力题 | 写明题设、假设、最坏情况及证明 | 不把记住的数字当成论证 |

## 项目面试的诚实表达

可以把技术准备分成四层：

- **读过：** 能定位实现文件或官方文档，解释主要流程，尚未运行。
- **复现过：** 在某个明确环境运行过，保存输入和输出，但不等于设计了原方案。
- **改过并验证：** 能展示自己改动的差异、测试以及未解决问题。
- **设计并承担：** 能解释需求取舍、失败处理、效果证据和实际职责。

例子：“我参考一个公开仓库理解了outbox流程，自己写了一个重复投递实验验证幂等；原仓库的生产负载我没有接触。”这比把公开项目所有功能说成自己的贡献更经得起追问。

AI辅助写代码也应具体说明：你负责定义什么需求，审查了哪些变化，用什么测试发现错误，最终哪些部分仍不确定。不能因代码是AI生成就省略理解，也不必否认使用工具。面试答案中的吞吐量、准确率、样本数只有实际记录可支持时才能改写成自己的成果。

## 面经的用法

先在[公开面经](../60-interviews/agent.md)中标出与目标岗位相关的问题，再回讲义查机制与追问。面经样本帮助了解提问方式，不是官方题库。不同作者、岗位阶段和时间的样本不能相加当成考频统计。

每周留一张复盘表：本周能独立讲清的3点、最容易混淆的2点、下一周要运行的1个实验。复习时优先补证据薄弱的环节，而非不停新增资料。

<a id="resume-to-questions"></a>
## 把简历的一句话变成可核验的追问清单

以虚构简历句子“实现了知识问答缓存，降低重复请求成本”为例，逐层生成问题：

1. **范围：** 缓存模型最终答案、检索结果还是嵌入？键包含哪些影响结果的参数？
2. **机制：** 命中、失效、并发回源怎样工作？权限和租户是否属于键或查询约束？
3. **证据：** 成本基线、样本选择、命中率和结果正确性如何记录？有无真实前后对照？
4. **失败：** 文档改动、权限撤回、模型版本变化、缓存服务故障时会发生什么？
5. **贡献：** 哪些代码由自己修改，哪些借鉴框架，哪些由AI生成并由自己验证？

只写实际能支持的回答。若目前只是读过实现，可以把该句改为学习记录，不放成已有工程成果。针对一个项目画出请求路径、存储边界和故障时间线，再练习从任何节点被打断后仍能解释其上下游。

<a id="cache-interview-ladder"></a>
## 缓存项目的递进式模拟面试

下面是原创模拟路线，不是任何公司的真实面试记录：

- **第一层，正常路径：** 用户请求如何构造键、查缓存、回源与写回？让候选人用一个具体ID走流程。
- **第二层，更新一致性：** 数据库成功而删缓存失败怎么办？另一个旧读请求在失效后写回旧值怎么办？要求画并发时间线，不接受只说“双删”或“延迟一会儿”。
- **第三层，压力与故障：** 热点同时过期、Redis不可用、数据库容量有限如何处理？区分单飞合并、过期抖动、降级、限流与负缓存的适用条件。
- **第四层，锁的失效：** 锁租约过期后旧持有者仍在运行，谁来拒绝它的写入？解释随机token安全解锁与递增fencing token的不同职责；业务操作还需幂等或版本校验。
- **第五层，证据与取舍：** 使用合成负载还是实际流量？哪些延迟分位、错误率和一致性失败被记录？如果只有小规模本地测试，就明确它不能证明生产容量。

练习时每层只加一个新故障，并给自己2分钟画图、1分钟答题、1分钟说限制。可查[缓存基础](../40-backend/03-redis-and-caching.md)、[可靠性](../40-backend/05-system-design-and-reliability.md)与[项目事实边界](../50-projects/public-repository-case-studies.md)。如果某层无法解释，回到对应原理与实验，而不是往答案里继续堆组件名称。
