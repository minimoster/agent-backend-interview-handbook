### G23 [P0] 什么是逃逸分析？返回局部变量指针安全吗？

**知识点详解**

逃逸分析是编译器对对象生命周期和引用关系的判断：对象能否安全放在当前栈帧等短生命周期空间，还是要放到更长生命周期的存储中。返回局部变量地址在 Go 中是安全的，编译器会保证它在仍被使用时有效，不会像错误 C 代码那样留下悬空栈指针。

逃逸不是只按语法判定。传接口、闭包捕获、动态大小、函数是否内联等都可能影响编译结果，且编译器会改进。应看 `go build -gcflags='-m=2'` 的诊断，再用 benchmark 的分配指标验证，不能把“取地址必逃逸”当规则。

**具体例子** ：返回 `&Result{...}` 的函数被内联后，如果结果只在调用方局部使用，实际可能不必堆分配。为减少所谓逃逸而改成全局对象，反而可能引入锁、共享状态和更长保留时间。

**面试答法** ：先讲生命周期与安全性，再讲编译诊断和实测。只有确认分配是热点后，才用预分配、复用、减少转换等优化。

**常见追问** ：栈一定比堆快多少？没有跨场景固定倍数；GC 压力、对象大小、内联等共同影响。

**误区** ：new 必上堆；能返回地址说明变量原来不在局部；逃逸越少整体程序一定越快。

### G24 [P0] Go GC 如何判断垃圾？三色、写屏障、STW 分别解决什么？

**知识点详解**

垃圾不是“值为 nil”或“创建很久”，而是从根无法再到达的对象。根可以理解为全局变量、G 栈等入口；沿引用找出仍活着的对象，未标记部分才有机会回收。主线是 tracing/mark-sweep：追踪引用、标记存活、清扫可回收空间。

三色是理解标记进度的模型：白色尚未确认可达，灰色已发现但内部引用待扫描，黑色已扫描。应用与标记器并发运行时，应用修改引用可能让标记器漏掉仍需要的对象，写屏障就是在关键指针写入时维护标记正确性的额外动作。STW 是短暂停止应用执行以协调阶段，不表示整个 GC 都暂停应用。

**具体例子** ：标记器刚扫过 A，业务又让 A 指向 B；若完全不记录这种变化，B 可能被错误当垃圾。写屏障、根扫描及阶段协议协同防止这种遗漏，而不是靠“GC 跑得足够快”。

**面试答法** ：先解释可达性，再讲并发标记为什么需要协调。Go 1.26 默认启用 Green Tea，优化扫描局部性与并行效率；基础原理仍要理解，不把旧实现细节当语言承诺。

**常见追问** ：有 GC 还会内存泄漏吗？会，缓存、长寿命 G、切片等可能保留业务已不用的引用。三色是每个对象一定存三种颜色吗？它首先是算法解释模型。

**误区** ：Go 使用引用计数；GC 没有任何暂停；GC 能回收还被缓存持有的对象。

### G25 [P1] GOGC、GOMEMLIMIT 怎样影响延迟和内存？

**知识点详解**

GC 在 CPU 时间与内存空间间取舍。GOGC 影响下一次 GC 的堆增长目标：通常允许增长越多，GC 次数可能越少，但占用更多内存；调低则更频繁回收，消耗更多 CPU。现实目标还涉及根集合，不宜只背一个忽略栈与全局根的简化公式。

GOMEMLIMIT 是 Go 运行时的软内存限制，并非操作系统硬上限，也不覆盖所有进程外部资源。限制过低、活数据本身太大时，可能出现频繁 GC，仍不能保证永不 OOM。容器里应给非 Go 内存、线程栈、映射及运行环境留空间。

**具体例子** ：容器只有 512MiB，却设置运行时软限制 512MiB，没有留出额外开销，仍可能被杀。正确做法是测活堆、分配速率、GC CPU 与尾延迟，再设置有余量的目标；这里不凭空给固定安全百分比。

**面试答法** ：先减少不必要的分配和长期引用，再讨论参数；每次改动都比较吞吐、P99、RSS、活堆和 GC 次数。

**常见追问** ：`GOGC=off` 就没有 GC 吗？设置内存限制时，运行时仍可能为了限制而执行 GC。降低限制为何可能让接口更慢？标记与应用争抢 CPU。

**误区** ：把 RSS 与 heap 完全等同；宣称调某个数即可根治 OOM。

### G26 [P1] sync.Pool 适合缓存数据库连接或任务结果吗？

**知识点详解**

sync.Pool 是可丢弃临时对象的复用池，用于减少重复分配。池中对象可能被运行时移除，Get 不保证拿到之前 Put 的对象，因此它不是可靠缓存、持久存储或有上限且可管理生命周期的连接池。

Put 后就应视为交出所有权，不能继续在原 G 使用。取出可复用 buffer 后要重置状态，避免上个请求残留内容；极大容量对象直接回池，可能长期抬高内存占用，因此可以规定最大可复用容量。是否值得用要靠分配与吞吐测试。

**具体例子** ：序列化 JSON 的临时 bytes.Buffer 可尝试复用；“每个用户会话的唯一状态”不能仅放 Pool，下一次可能根本拿不到。数据库连接应由 database/sql 等专门的连接管理机制负责。

**面试答法** ：强调临时、可丢、减少分配；给出状态重置、容量上限、所有权转移三项约束。

**常见追问** ：Pool 能保证最多 N 个对象吗？不能。为什么复制 Pool 不合适？使用后复制会破坏同步对象的使用约定。

**误区** ：Pool 可以当 map 缓存；Get 出来的对象天然是干净的；越多对象放进池越省内存。
