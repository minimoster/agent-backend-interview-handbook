# 算法与 SQL 练习单

[返回总目录](../../README.md) · [题目索引](../../QUESTION_INDEX.md) · [版本与纠错](../../errata/README.md)

**算法入口**： LeetCode 75。按数据结构分块学习，不照单全刷。结合[统一学习路线](../00-guide/expanded-map-and-study-plan.md)少量选题并反复重做；基础薄弱时，减少新题、增加复盘。

- 数组/哈希：两数之和、去重、频次统计。验收：解释哈希查找的常见复杂度假设与额外空间。
- 双指针/窗口：有序数组去重、最长无重复子串、正数数组最短达标子数组。验收：说清左右边界与适用前提。可用官方题页练习 B49 的正数前提。
- 二分：查找目标、边界位置。验收：说明闭区间或半开区间不变量，避免死循环。
- 链表/栈队列：反转链表、判环、括号匹配。验收：手画更新顺序，覆盖空链表。
- 树/堆：层序遍历、路径问题、Top-K。验收：区分递归栈空间、堆容量与排序成本。
- 基础 DP：爬楼梯、打家劫舍、简单背包变体。验收：先定义状态与边界，再写转移；不以背代码替代推导。

**SQL 入口**： SQL 50。建议先做约 15—20 道，至少用 5 个自造反例验证。以下表与问题可在选定数据库本地建表复现；这些练习尚未执行数据库集成测试。

练习表：users(id,name)，orders(id,user_id,amount,status,created_at)，enrollments(student_id,course_id)。id 为各实体主键；课程记录故意允许重复，方便练习去重。

1. 查没有订单的用户：分别用 NOT EXISTS 和 LEFT JOIN 后检查订单主键 IS NULL。加入一个同名用户，验证不应按姓名连接。
2. 统计每个用户已支付订单总金额：先明确是否保留零订单用户；需要保留时，把支付状态条件放进 JOIN 条件，并用 COALESCE 处理空聚合结果。
3. 查总金额超过 1000 的用户：按 user_id 分组，使用 HAVING SUM(amount)&gt;1000；再明确只统计哪种订单状态。
4. 查每人最近三条订单：用 ROW_NUMBER；加入两条时间完全相同的订单，检查唯一键是否参与排序。
5. 查每个用户最高订单金额及对应订单：先明确并列时返回一条还是全部，再选 ROW_NUMBER 或 RANK。
6. 查恰好选两门不同课的学生：COUNT(DISTINCT course_id)=2；加入重复选课记录验证。
7. 分页读取时间线：分别写 OFFSET 和游标方案；解释数据变化期间的重复、遗漏与一致性取舍。
8. 原子扣库存：用两个数据库会话并发执行 B18 的 SQL，记录成功次数、受影响行数和最终库存。

每道题的复盘固定回答：表中“一行代表什么”？会不会连接扩增？NULL 怎么处理？排序是否稳定？需要哪些索引？结果正确性与性能是否分别验证？聚合函数的NULL、空集和类型行为需按目标PostgreSQL版本核对。
